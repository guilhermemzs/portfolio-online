Beyond 3D models: using BIM to organise information for decisions

The value of a BIM model depends on whether other people can use its information for a defined decision.

By Guilherme Menezes Pereira · Editorial date 13 September 2026

Abridged English edition · Portuguese original published 6 November 2026

Look beyond the visual model

A three-dimensional representation makes spaces and clashes easier to discuss. It can still leave a maintenance team without a usable equipment identifier. This article explores information management through hypothetical examples drawn from my interests in technology and civil engineering.

Start with the intended decision

In a hypothetical school refurbishment, reorganising classrooms requires dimensions, use and spatial constraints. Planning equipment maintenance requires identifiers, locations, specifications and access. Specify the intended use, the required fields and how the recipient will check the delivery.

Plan the work and the exchanges

Penn State’s BIM Project Execution Planning Guide connects model uses, processes, information exchanges and supporting infrastructure. For the school example, the team might begin with spatial coordination and maintenance data, naming owners, review points and deliverables for each.

Assign responsibilities explicitly

Producing, reviewing, authorising and accepting information are distinct tasks. Checking file structure does not qualify someone to approve a structural calculation. Record the purpose, producer, reviewer, authorisation, deadline and evidence of completion for each delivery.

Define a common data environment

A CDE combines technical tools with a workflow. Show which revision is in development, shared for coordination, published for use or archived. If a wall opening moves, procurement and construction teams need to identify the authorised revision and see what changed.

Test interoperability

IFC supports open exchange of information about built assets. Agree the version, content and intended use before exchanging files. In a small trial, compare ten representative elements before and after transfer. A door can remain visible while losing the code that links it to a maintenance record.

Review information in layers

Check that the file opens and contains the intended elements. Then check units, classifications and properties. Finally, test whether the result supports the decision it was delivered for. Document the software versions, procedure and any accepted limitations.

Connect engineering with systems

A shared folder or a visually convincing model cannot supply missing responsibilities. The ability to specify, verify and explain information is part of the engineering work, alongside learning to model.
